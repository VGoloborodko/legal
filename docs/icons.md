# Icons

`Icons` — это система локальных SVG-иконок проекта.

Она нужна, чтобы все иконки в проекте были устроены одинаково: имели единые правила по структуре файлов, размеру, цвету, доступности и использованию в компонентах. Это особенно важно, потому что проект уже использует общий компонент `Icon`, общую карту `icons` и единый API для передачи иконок, в том числе в `Button`. 

## Зачем нужна система иконок

Система иконок нужна для того, чтобы:

- все иконки подключались и использовались единообразно;
- SVG-компоненты имели одинаковый контракт;
- новые иконки добавлялись без хаоса и дублирования;
- `Icon` оставался единой точкой входа для большинства сценариев;
- поведение иконок в `Button`, секциях, карточках и других компонентах было предсказуемым;
- документация соответствовала реальной реализации.

## Структура

Рекомендуемая структура файлов:

```text
app/components/ui/icon/
  Icon.tsx
  icon.types.ts
  icons.ts
  icons/
    ArrowRightIcon.tsx
    ArrowUpRightIcon.tsx
    ShieldIcon.tsx
```

### Назначение файлов

- `Icon.tsx` — общий компонент-обёртка для рендера иконки по имени.
- `icon.types.ts` — базовые типы для SVG-иконок и общего API.
- `icons.ts` — registry всех доступных иконок.
- `icons/` — директория с конкретными SVG-компонентами.

Такое разделение помогает не смешивать системные файлы и конкретные SVG-иконки в одной плоскости.

## Общие правила системы

### 1. Основной способ использования — через `Icon`

Базовый способ работы с иконками в проекте — использовать общий компонент `Icon`.

```tsx
<Icon name="shield" />
```

Это даёт единый API, типизацию по `IconName` и единый способ использования во всех частях проекта.

### 2. Прямой импорт SVG-иконки допустим, но не является основным

Иногда конкретную SVG-иконку можно использовать напрямую:

```tsx
<ShieldIcon size={18} stroke="var(--color-text-primary)" />
```

Это допустимо для частных случаев, но в большинстве сценариев предпочтителен именно `Icon`.

### 3. Все иконки должны быть локальными SVG-компонентами

Иконки внутри дизайн-системы не должны жить как сырые `.svg`-файлы без общего контракта. Каждая системная иконка должна быть React-компонентом с единым набором пропсов.

## Соглашения по именованию

### Имена файлов

Файлы конкретных SVG-компонентов именуются в `PascalCase`:

- `ArrowRightIcon.tsx`
- `ArrowUpRightIcon.tsx`
- `ShieldIcon.tsx`

### Имена в registry

Ключи в `icons.ts` именуются в `camelCase`:

- `arrowRight`
- `arrowUpRight`
- `shield`

### Имена типов

Если имя иконки выводится из объекта `icons`, то тип `IconName` должен автоматически строиться из его ключей.

Пример:

```tsx
export const icons = {
  arrowRight: ArrowRightIcon,
  arrowUpRight: ArrowUpRightIcon,
  shield: ShieldIcon,
};

export type IconName = keyof typeof icons;
```

Такой подход исключает рассинхрон между реестром и типами.

## Устройство системы

## `Icon.tsx`

`Icon` — это общий компонент-обёртка, который получает имя иконки и рендерит нужный SVG-компонент из `icons.ts`.

Его задача:

- принять `name`;
- найти нужную иконку в общей карте;
- передать в неё стандартные SVG-пропсы;
- сохранить единый API для всего проекта.

Пример использования:

```tsx
<Icon name="arrowUpRight" size={18} />
```

## `icon.types.ts`

`icon.types.ts` содержит базовые типы, которые используются в иконках и в компоненте `Icon`.

Минимально здесь должен быть общий тип пропсов SVG-иконки:

```tsx
import type { SVGProps } from 'react';

export type IconBaseProps = SVGProps<SVGSVGElement> & {
  size?: number | string;
  width?: number | string;
  height?: number | string;
  fill?: string;
  stroke?: string;
};
```

Если в проекте есть отдельный тип для общего `Icon`, его тоже стоит держать рядом в этой же директории.

## `icons.ts`

`icons.ts` — это единая карта доступных иконок.

Пример:

```tsx
import ArrowRightIcon from './icons/ArrowRightIcon';
import ArrowUpRightIcon from './icons/ArrowUpRightIcon';
import ShieldIcon from './icons/ShieldIcon';

export const icons = {
  arrowRight: ArrowRightIcon,
  arrowUpRight: ArrowUpRightIcon,
  shield: ShieldIcon,
};

export type IconName = keyof typeof icons;
```

Именно этот файл определяет, какие иконки доступны через `Icon`.

## `icons/`

Папка `icons/` содержит конкретные SVG-компоненты. Каждый такой компонент отвечает только за собственную SVG-разметку и не должен содержать лишнюю UI-логику.

## Требования к SVG-иконкам

Каждая SVG-иконка в системе должна следовать одним и тем же правилам.

### Поддерживаемые пропсы

Каждый SVG-компонент должен принимать:

- `size`
- `width`
- `height`
- `fill`
- `stroke`
- `className`
- `...props`

Это нужно, чтобы все иконки были взаимозаменяемыми по API и могли одинаково использоваться через `Icon`.

### `size`, `width`, `height`

Иконка должна поддерживать как общий размер через `size`, так и отдельные значения `width` и `height`.

Ожидаемая логика:

- если передан `size`, он используется как значение по умолчанию для `width` и `height`;
- если `width` или `height` переданы явно, они имеют приоритет над `size`.

Пример:

```tsx
const resolvedWidth = width ?? size;
const resolvedHeight = height ?? size;
```

Это делает API гибким и предсказуемым.

### `viewBox` обязателен

У каждой SVG-иконки обязательно должен быть `viewBox`.

Пример:

```tsx
<svg
  viewBox="0 0 24 24"
  width={resolvedWidth}
  height={resolvedHeight}
  ...
>
```

Без `viewBox` иконка может масштабироваться неправильно. Это уже было отмечено в аудите как реальная проблема в одной из иконок, поэтому правило должно быть обязательным для всех новых SVG-компонентов.

### Проброс `...props` обязателен

Все дополнительные SVG-пропсы обязательно должны пробрасываться в корневой `<svg>`.

Правильно:

```tsx
<svg
  width={resolvedWidth}
  height={resolvedHeight}
  viewBox="0 0 24 24"
  className={className}
  {...props}
>
```

Это нужно для поддержки:

- `aria-*`
- `data-*`
- `role`
- `onClick`
- `style`
- `focusable`
- других стандартных SVG-атрибутов

Если `...props` не пробрасываются, иконка теряет гибкость и хуже интегрируется в компоненты.

### `fill` и `stroke`

Иконка должна поддерживать и `fill`, и `stroke`, если это уместно для её SVG-структуры.

Есть два типовых сценария:

1. fill-иконки — цвет задаётся через `fill`;
2. stroke-иконки — цвет задаётся через `stroke`.

Примеры:

```tsx
<Icon name="arrowUpRight" fill="var(--color-text-brand)" />
<Icon name="shield" stroke="var(--color-text-primary)" />
```

Если конкретная иконка по своей природе полностью заливочная, `stroke` может не использоваться внутри paths. Если иконка построена на обводках, основным будет `stroke`.

### `currentColor` допустим как дефолт

Если иконка должна наследовать цвет текста родителя, допустимо использовать `currentColor`.

Примеры:

```tsx
<Icon name="shield" stroke="currentColor" />
<Icon name="arrowUpRight" fill="currentColor" />
```

Это особенно удобно в кнопках, ссылках, инлайновых UI-элементах и местах, где цвет задаётся через `color` у родителя.

Пример:

```tsx
<span style={{ color: 'var(--color-text-brand)' }}>
  <Icon name="shield" stroke="currentColor" />
</span>
```

В таком случае иконка автоматически наследует цвет контейнера.

### Цветовые токены

Для цвета иконок нужно использовать текстовые токены или `currentColor`.

Корректные примеры:

```tsx
<Icon name="shield" stroke="var(--color-text-primary)" />
<Icon name="shield" stroke="var(--color-text-secondary)" />
<Icon name="shield" stroke="var(--color-text-brand)" />
<Icon name="arrowUpRight" fill="var(--color-text-brand)" />
<Icon name="arrowUpRight" fill="currentColor" />
```

Не рекомендуется использовать фоновые токены вроде `--color-bg-*` как основной цвет самой иконки, потому что они предназначены для поверхностей и контейнеров, а не для семантического цвета контента.

## Рекомендуемый шаблон SVG-иконки

Ниже базовый шаблон, на который стоит ориентироваться при добавлении новой иконки:

```tsx
import type { IconBaseProps } from '../icon.types';

export default function ExampleIcon({
  size = 24,
  width,
  height,
  fill = 'none',
  stroke = 'currentColor',
  className = '',
  ...props
}: IconBaseProps) {
  const resolvedWidth = width ?? size;
  const resolvedHeight = height ?? size;

  return (
    <svg
      width={resolvedWidth}
      height={resolvedHeight}
      viewBox="0 0 24 24"
      fill="none"
      xmlns="http://www.w3.org/2000/svg"
      className={className}
      {...props}
    >
      <path
        d="..."
        stroke={stroke}
        strokeWidth="1.5"
        strokeLinecap="round"
        strokeLinejoin="round"
      />
    </svg>
  );
}
```

Если иконка заливочная, логика будет такой же, но путь будет использовать `fill={fill}`.

## Доступность

Иконки должны использоваться с учётом того, несут ли они смысловую нагрузку или являются декоративными.

### Декоративные иконки

Если иконка только дополняет текст и не несёт отдельного смысла, она должна быть скрыта от assistive technology.

Обычный подход:

```tsx
<span aria-hidden="true">
  <Icon name="arrowRight" />
</span>
```

Или сама иконка может рендериться как декоративная, если это предусмотрено реализацией.

### Смысловые иконки

Если иконка передаёт смысл без текста рядом, у неё должна быть доступная подпись.

Например, для icon-only элемента:

```tsx
<button aria-label="Открыть меню">
  <Icon name="menu" />
</button>
```

Или у SVG могут быть переданы нужные `aria-*` атрибуты через `...props`.

### Иконки внутри Button

Если иконка находится внутри кнопки рядом с текстом и не добавляет отдельного смысла, она должна быть декоративной.

Типичный сценарий:

```tsx
<Button icon={{ name: 'arrowUpRight' }}>
  Подробнее
</Button>
```

В таком случае текст кнопки уже даёт доступное название, а иконка не должна дублировать его для screen reader.

## Использование в компонентах

### Напрямую в JSX

```tsx
<Icon name="shield" size={18} stroke="var(--color-text-primary)" />
```

### Через объект-конфиг

Если компонент принимает иконку снаружи, нужно использовать объект-конфиг, совместимый с API `Icon`.

Пример:

```tsx
<Hero
  icon={{
    name: 'shield',
    size: 18,
    stroke: 'var(--color-text-primary)',
  }}
/>
```

Внутри компонента:

```tsx
{icon && <Icon {...icon} />}
```

Такой формат нужен для единообразия и переиспользуемости.

### Использование в Button

Для `Button` используется object API.

Правильный формат:

```tsx
<Button icon={{ name: 'arrowUpRight' }}>
  Отправить
</Button>
```

Если нужно, можно передать дополнительные свойства иконки:

```tsx
<Button
  icon={{
    name: 'arrowUpRight',
    size: 18,
  }}
>
  Отправить
</Button>
```

### Размер иконки внутри Button

Внутри `Button` действует локальное правило:

- у кнопки есть собственный дефолтный размер иконки;
- этот размер единый для всех размеров кнопки;
- он не зависит от `md` или `lg`;
- если `size` передан вручную в объекте `icon`, он переопределяет дефолтный размер кнопки;
- это правило относится только к `Button` и не является глобальным поведением всей системы иконок.

## Добавление новой иконки

### Шаг 1. Создать SVG-компонент

Создать новый файл в `icons/`, например:

```text
app/components/ui/icon/icons/PhoneIcon.tsx
```

### Шаг 2. Реализовать компонент по общему контракту

Новая иконка должна:

- принимать `size / width / height / fill / stroke / className / ...props`;
- иметь `viewBox`;
- пробрасывать `...props` в корневой `<svg>`;
- использовать `currentColor` как дефолт там, где это уместно.

### Шаг 3. Подключить иконку в `icons.ts`

Пример:

```tsx
import PhoneIcon from './icons/PhoneIcon';

export const icons = {
  arrowRight: ArrowRightIcon,
  arrowUpRight: ArrowUpRightIcon,
  shield: ShieldIcon,
  phone: PhoneIcon,
};
```

### Шаг 4. Убедиться, что имя попало в `IconName`

Если `IconName` строится от `keyof typeof icons`, дополнительной ручной синхронизации не потребуется.

### Шаг 5. Проверить использование

После этого иконка должна быть доступна так:

```tsx
<Icon name="phone" />
```

## Список доступных иконок

На текущий момент набор иконок определяется содержимым `icons.ts`.

Пример:

- `arrowRight`
- `arrowUpRight`
- `shield`

Если в проект добавляются новые иконки, этот список должен пополняться вместе с `icons.ts`.

## Рекомендации

- Использовать `Icon` как основной способ рендера иконок.
- Хранить конкретные SVG-иконки отдельно от системных файлов.
- Соблюдать единый контракт пропсов для всех SVG-компонентов.
- Всегда добавлять `viewBox`.
- Всегда пробрасывать `...props` в корневой `<svg>`.
- Использовать `currentColor` там, где иконка должна наследовать цвет текста.
- В переиспользуемых компонентах передавать иконку через объект, совместимый с `Icon`.
- Не использовать старые альтернативные API, если в системе уже принят единый формат.

## Частые ошибки

### Нет `viewBox`

Это ломает корректное масштабирование SVG.

### Нет `...props` в `<svg>`

Это ограничивает доступность и повторное использование.

### Разные API у разных иконок

Если одна иконка принимает `size`, а другая нет, система становится непредсказуемой.

### Смешение naming-стилей

Файлы должны быть в `PascalCase`, а ключи в `icons.ts` — в `camelCase`.

### Использование иконки напрямую без причины

Если в проекте уже есть `Icon`, лучше не размножать разные способы подключения одной и той же иконки.

### Иконка озвучивается screen reader без необходимости

Если иконка декоративная, она не должна дублировать текст для пользователя assistive technology.
